# RCA — torneo-platform deploy run `ff19fb83-117b-402c-9f9c-cc03196d37b4`

## Verdict
Failed step: **deploy_k8s** (rollout never became ready). The real cause is **not** infra or a manifest — the **backend crashes on startup** with a MongoDB `DuplicateKeyError`, so nginx `/health` returns 503 / connection-refused, the startup probe fails on every restart, and the Deployment times out waiting to become ready. This is an **application source/data bug**. Re-running the pipeline on the same code will fail identically — do NOT just redeploy.

## Evidence
Crash during FastAPI startup lifespan:
```

torneo-platform-test_database.players index: link_code_1 dup key: { link_code: null }
...
File "/app/backend/app/seed.py", line 303, in seed_match_engine
  await players.insert(Player(tournament_id=..., first_name=fn, ... ), actor.id)
File "/app/backend/server.py", line 154, in startup -> seed_all() -> seed_match_engine()
ERROR:    Application startup failed. Exiting.
Backend died, shutting down nginx...
nginx: connect() failed (111: Connection refused) ... GET /health -> upstream 127.0.0.1:8001
```
Pod events: `Startup probe failed: HTTP 503` / `connection refused`, `BackOff restarting failed container` on both replicas → `deployment failed to become ready: timed out waiting for the condition`.

Live deployed DB (`torneo-platform-test_database`) confirms the setup:
- `players` index `link_code_1` = `{ sparse: true, unique: true }`.
- `count({link_code: null})` = **1** — a player with an explicit null `link_code` already exists.

Serialization proven in the eph sandbox against the run's own source:
- `BaseDocument.to_mongo()` = `self.model_dump(by_alias=True)` with **no `exclude_none`**.
- `Player.link_code: Optional[str] = None`.
- Constructing a seed `Player(...)` and calling `to_mongo()` yields `link_code present in doc: True | value: None` — i.e. the field is written as an **explicit `null`**, not omitted.

## Root cause
A **`sparse` unique index does NOT skip documents that contain the field set to an explicit `null`** — it only skips documents where the field is entirely absent. Because `to_mongo()` always emits `link_code: null` for players created without a code, every such insert is indexed under the same `null` key and the second one violates uniqueness.

`seed_match_engine` (`app/seed.py` ~line 303) is the **only** insert path that creates `Player(...)` **without** a `link_code` — every other path sets one (`app/routers/roster_imports.py:333` and `app/routers/matches.py:219` both pass `link_code=linkcodes.new_code()`). On startup `seed_all()` runs before `ensure_link_codes()`; `seed_match_engine` only runs when the tournament exists but has zero matches (`if not t or scoped("matches", t.id).count() > 0: return`). Prior deploys had matches already seeded, so this block was skipped and the latent bug never fired. On this run the DB was in a fresh/partial state (tournament present, 0 matches, 1 null-link_code player already there), so seeding inserted a second `link_code: null` player → immediate `E11000` → startup abort → deploy_k8s timeout.

## Fix (Code — E1 to apply in the source repo, then re-trigger the deploy)
Apply **both**; part 1 is the root-cause fix, part 2 removes the direct trigger.

### 1. Make the index tolerate multiple nulls — `app/backend/app/services/linkcodes.py` (`ensure_link_codes`, line 18)
Replace the `sparse` unique index with a **partial** unique index that only enforces uniqueness on real string codes (this matches the convention already used throughout `app/backend/app/migrations.py`). The existing index has the same key but different options, so it must be dropped first:
```python
# was: await db.players.create_index("link_code", unique=True, sparse=True)
try:
    await db.players.drop_index("link_code_1")
except Exception:
    pass
await db.players.create_index(
    "link_code",
    unique=True,
    partialFilterExpression={"link_code": {"$type": "string"}},
    name="link_code_1",
)
```
This makes any number of `link_code: null` players legal while still guaranteeing uniqueness of issued codes. It also cleanly tolerates the 1 pre-existing null player already in prod.

### 2. Give seeded players a code — `app/backend/app/seed.py` (`seed_match_engine`, ~line 303)
Match every other insert path:
```python
from .services import linkcodes
...
await players.insert(
    Player(
        link_code=linkcodes.new_code(),
        tournament_id=t.id, club_id=club.id, team_id=team.id,
        first_name=fn, last_name=ln, birth_year=2014,
        shirt_number=num, role=role,
        profile_visibility="public" if i % 3 else "private",
        media_consent=bool(i % 3),
    ),
    actor.id,
)
```

(Optional hardening: have `BaseDocument.to_mongo()` / the Player insert omit `link_code` when `None` so a null is never written — but parts 1+2 fully resolve the crash.)
